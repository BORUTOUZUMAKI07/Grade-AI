# Grade-AI

Grade-AI is an educational student-outcome analytics demo built with React, FastAPI, and R. It demonstrates two supervised classifiers—**Logistic Regression** and **Decision Tree**—alongside **PCA (2 components)** and **K-Means (2 clusters)**. The two unsupervised transforms are applied to new student inputs as supplementary analysis, not as independent Pass/Fail classifiers.

> **Important demo limitation:** The included dataset is generated synthetic data (1,000 rows; 500 Pass and 500 Fail). It is not a representative or independently collected student dataset. Do not use this project or its outputs to make real academic, admission, disciplinary, or other high-impact decisions. The displayed probabilities are not calibrated for real-world outcomes.

## Model roles

| Component | Purpose | Predicts Pass/Fail? |
|---|---|---|
| Logistic Regression | Binary supervised classifier; standardized inputs | Yes |
| Decision Tree | Binary supervised classifier with a decision path | Yes |
| PCA (2 components) | Transforms new inputs with training-fitted loadings; provides a 2D projection and optional classifier features | No, not by itself |
| K-Means (2 clusters) | Assigns new inputs to a learned cluster and shows the descriptive training-cluster outcome share | No, not by itself |

Every single-student prediction response now also includes a PCA projection and K-Means cluster assignment when artifacts are present. These are supplementary unsupervised outputs. Cluster Pass rates are descriptive in-sample training-set shares, not validated individual risk probabilities. The supervised prediction selector remains limited to Logistic Regression and Decision Tree.

## Evaluation design

The R pipeline generates a reproducible stratified 80/20 holdout (seed 20260925). The 80% training partition is used for five-fold stratified cross-validation; preprocessing is fitted within each fold. The outer 20% test partition is held out from CV and is used for final reported evaluation metrics.

Reported holdout metrics include accuracy, precision, recall, specificity, F1, ROC-AUC, confusion matrix, majority-class baseline, Brier score, and a descriptive reliability-bin summary. Cross-validation accuracy and log-loss are reported separately as training-partition diagnostics. Final app artifacts are refit on all approved synthetic rows after evaluation; they are not the holdout models.

Because the source labels and features are synthetic and generated by a simple class-conditioned process, these scores only validate pipeline behavior on this artificial demo. They do not establish real-world predictive validity, fairness, calibration, or causal effects. No hyperparameter search or probability-calibration procedure is currently claimed.

## Generate data and train

Requirements: Python 3 and R with the R packages `rpart` and `jsonlite`.

From the repository root:

```bash
python r_analytics/data/generate_balanced_dataset.py
Rscript r_analytics/src/train.R
```

Training writes these files to `backend/model_store/`:

- `decision_tree_model.json` — tree structure and reference synthetic records.
- `logistic_regression_model.json` — standardized coefficients and feature center/scale.
- `pca_model.json` — centers, scales, loadings, explained variance, and scores.
- `kmeans_model.json` — standardized cluster centers, sizes, and assigned records.
- `analytics_summary.json` — dataset summaries, held-out evaluation, and CV diagnostics.

GitHub Actions runs application checks and the training/validation workflow. The training workflow validates artifacts, commits refreshed model artifacts and generated synthetic data, and uploads a workflow artifact.

## Run locally

### Backend

```bash
cd backend
pip install -r requirements.txt
cp .env.example .env
# Set a strong SECRET_KEY and ADMIN_EMAIL in .env
python -m app.main
```

Register the account matching `ADMIN_EMAIL` to grant it admin role.

### Frontend

```bash
cd frontend-react
npm install
npm run dev
```

Open the Vite URL shown in the terminal (normally http://localhost:5173).

## API overview

- `GET /api/v1/predict/models` — registered supervised prediction models; the single prediction response additionally returns supplementary PCA/K-Means analysis.
- `GET /api/v1/predict/analytics` — model summary, PCA, and clustering artifacts (authorized staff access).
- `POST /api/v1/predict/` — prediction with `model: "decision_tree"` or `"logistic_regression"`.
- `POST /api/v1/predict/batch` — batch predictions with the same two model choices.

## Roles

- **admin:** teacher capabilities plus user/role management and usage statistics.
- **teacher:** classes, students, batch predictions, and PDF reports.
- **student:** single predictions and personal history.

## Before any real-world use

A credible real-world model would require a lawfully collected, documented, consented/permissioned dataset; a target definition and prediction horizon; leakage review; representative temporal or external validation; subgroup error and fairness analysis; calibration analysis; privacy/security review; human oversight; and ongoing monitoring. Do not commit personal or sensitive student data, credentials, or secrets.

For deployment, configure strong secrets, HTTPS, production database migrations and backups, rate limits, access controls, logging/retention policies, and platform-specific environment variables. This repository's demo pipeline is not a certified or production-validated academic decision system.
